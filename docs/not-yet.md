# Not yet

What this game does not do yet, each with where the detail is.

- **A Workshop map is a course document, not a scene.** `provides.json` accepts kind `map`, `map_kind` `deathrun`. The entry is `{"kind": "map", "map_kind": "deathrun", "scene": "<path>.json"}`: `scene` names the same JSON document `courses/` holds (see `courses/README.md`). The document is the whole map: its `traps` (parts on a timeline, with their buttons), `start`, `activators` (the walkway), `finish` and `end` are what supply the traps and the runner/death sides, so a pack ships no code. `DrCatalogue.follow_content` re-reads the index on every `playable_courses()`, so solo lists and plays it as "Name [Pack]" and an online session lists none; the game's own ids (including `dr_practice`) win.
- **A pack course cannot bring its own art or sound.** The document names looks, roles, `ambience` and `surface` from the game's own sets (`DrTextures`, `DrAudio`); there is no path field for a pack texture or stream, so a pack course uses the shipped prototype look. Adding one is a document-format change (validator, builder and the copy that travels to clients), not an addon change.
- **A pack course claiming an id of the game's own can show on the ballot.** The catalogue keeps the game's course, but dot-vote's `follow_content` only de-duplicates against the ids in the source's own list, which leaves `dr_practice` out once there are other courses. The row reads "Name [Pack]"; choosing it is harmless because `DrGame` plays a next course only if the catalogue lists it. Fixing it needs a reserved-ids list on `DotVoteListSource`.
